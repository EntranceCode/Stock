# 本地A股数据检查与接入评估

检查日期：2026-10-07。数据目录：`D:\vscode\data\A股数据\parquet`。
用户提供的来源项目：`D:\vscode\AlphaMaster`。

本文记录首次原始数据检查。之后已完成日线参考比对、规范化及ETF/财务接口样本补充，更新结果见[数据准备进度](data-preparation-progress.md)；原始数据的分钟与指数问题仍然保留。

## 1. 结论

这批数据可以作为股票行情研究的候选输入，但目前不满足完整“个股多因子 + ETF轮动”回测的数据条件。股票日线基础价格检查通过；指数数据存在严重异常，分钟线时间精度存在损失，未找到ETF、财务、证券状态及公司行动等必需数据。

本次仅检查数据和来源代码，没有修改原始数据或AlphaMaster，没有生成投资收益或执行交易。AlphaMaster当前代码与这份历史导出之间的版本和生成链路尚未确认。

## 2. 检查范围与工具

- 遍历全部17,951个Parquet文件并读取元数据，所有文件均可读取。
- 全量读取4,487个日线文件，共15,170,674行，检查字段、空值、时间顺序、重复时间、OHLC关系、价格符号和成交量异常。

## 4. 字段与数据性质

全量文件的去除元数据后Schema一致：

| 字段 | 类型 | 当前能确认的意义 |
|---|---|---|
| time | int64 | 非标准秒时间戳；股票样本接近Unix秒除以1000 |
| open / high / low / close | float32 | OHLC价格；复权性质尚未得到导出链路证明 |
| tick_volume | int64 | 成交量类字段，不应按字段名推断为真实tick数 |

未包含成交额、换手率、流通股本、证券名称、交易所标记、ST状态、停牌标记、涨跌停价格、行业、财务指标、公告时间、复权因子、公司行动或ETF成分。

仅有股票/指数行情不能替代ETF成交数据；指数不是可下单证券。不能用这些文件中的普通价格涨跌直接验证价值或质量因子。

## 5. 股票日线检查结果

4,272个日线文件，共15,077,555行：

| 检查项 | 结果 |
|---|---:|
| 时间空值、重复时间、时间倒序 | 均为0 |
| 非有限价格、非正价格、OHLC关系异常 | 均为0 |
| 成交量空值、负成交量 | 均为0 |
| 成交量为0 | 14行，分布于13个文件 |
| 相邻收盘价绝对变动超过30% | 6,753行，分布于3,000个文件 |

OHLC检查容忍float32舍入误差。超过30%的变动是调查标记，不能直接视为坏数据，也不能删除：它可能涉及除权、上市初期、交易日间隔或其他事件，需要公司行动和证券状态对照。

单个股票日线长度最少4行、最多8,542行，中位数3,343行。新上市或短历史证券必须在策略预热和股票池筛选中排除。

在“time乘1000后按epoch秒解读”的候选规则下，股票日期范围最早1990-12-19、最晚2026-07-07，全部4,272个股票日线的末日期候选值均为2026-07-07。这只是候选日历映射，时区及编码精度尚未核实；也不表示每只股票均有完整历史。截至检查日期，不能用于当前交易信号。

基础结构检查通过不等于时点、复权、全市场覆盖、退市处理和真实可交易性通过。

## 6. 时间编码与分钟线精度

样本`000001_daily`最后一行`time = 1783436`。直接当Unix秒会落在1970年；乘1000后得到2026-07-07 14:53:20的UTC标签，仍不能直接当作正确北京时间收盘时刻。

来源代码[parquet_manager.py](D:/vscode/AlphaMaster/data_pipeline/parquet_manager.py:180)记录了“秒/1000”的兼容问题，当前逻辑是对较小时间戳乘1000，再按时间去重。

整数保存意味着被截掉的秒数无法由乘法恢复。`000001_5min`共23,616行，只有7,872个不同time值，直接去重会丢失15,744行（约66.7%）。这些记录有不同价格和成交量，不能当作普通重复行删除。

| 分钟抽样组 | 抽查行数 | 重复time的额外行数 | OHLC异常行数 |
|---|---:|---:|---:|
| stocks / 5min | 237,264 | 158,176 | 0 |
| stocks / 15min | 79,088 | 5,985 | 0 |
| stocks / 60min | 18,596 | 0 | 0 |
| indices / 5min | 26,100 | 807 | 3,495 |
| indices / 15min | 9,303 | 147 | 1,533 |
| indices / 60min | 2,551 | 12 | 507 |

日线在确认时间编码与交易日历后可能恢复交易日期，不能据此声称恢复了精确成交时间。分钟线优先从未损失精度的原始数据重新导出；禁止凭行号插造5分钟时间。

## 7. 成交量单位

对`000001`按候选日期汇总5分钟成交量，与日线对齐，比例中位数为100。最近样本：

| 候选日期 | 日线tick_volume | 5分钟汇总tick_volume |
|---|---:|---:|
| 2026-07-06 | 1,061,048 | 106,104,900 |
| 2026-07-07 | 805,221 | 80,522,100 |

来源项目当前[通达信数据源](D:/vscode/AlphaMaster/web/data_sources/tongdaxin_source.py:156)注明不复权数据、成交量单位为手，时间来自北京时间。但当前数据源代码并不能证明这批已导出文件的每个周期都使用该单位或时区。样本支持日线与分钟线采用不同成交量尺度的判断，必须逐来源、逐周期核实后再转换为统一`volume_shares`。

现有文件缺少成交额，不应使用`close × tick_volume`冒充准确成交额。容量筛选暂缺可靠输入；如果使用估计值，只能作为明确标注的研究近似。

AlphaMaster当前[通达信指数分支](D:/vscode/AlphaMaster/web/data_sources/tongdaxin_source.py:142)区分指数与股票接口，其代码注释描述了指数误用股票接口时出现乱码的情况。这是可能的排查方向，尚未确认是本批数据损坏的确切原因。

初版将整个`indices`数据组标为待核验，不作为绩效基准或市场择时输入。应从正确市场与指数接口重新获取并与可信样本核对；不能只删除异常行后宣称指数已经有效。

## 9. 对混合策略设计的影响

| 原设计需求 | 当前数据支持程度 | 接入决定 |
|---|---|---|
| 股票动量与低波动研究 | 有OHLC历史，但复权/时间未核实 | 先做数据修复与事件核对，之后建立价格因子研究基线 |
| 股票质量与价值因子 | 缺财务、股本和公告时点 | 暂不能验证，保留原策略模块并补数据 |
| 历史可投资股票池 | 缺上市/退市、风险警示、权限与状态记录 | 不能仅使用目录里的现存代码构建无偏全市场回测 |
| 行业约束 | 缺历史行业与ETF穿透数据 | 补充后才能验证原约束 |
| ETF趋势轮动及防御ETF | 未发现ETF行情 | 单独补充ETF日线和证券元数据 |
| 交易容量与成本 | 缺成交额，成交量单位不一致 | 统一量纲，补成交额和适用规则 |
| 指数基准与市场择时 | 指数严重异常 | 隔离并重新核验数据来源 |

总体策略目标保持“个股选股 + ETF轮动 + 防御仓位”。研究顺序调整为：数据修复与字段补齐 → 股票价格因子基线 → 价值/质量因子与ETF单模块 → 混合组合验证。不得把暂时可计算的价格指标包装成已实现的财务多因子。

## 10. 接入约定与后续工作

源目录按只读对待。后续规范化数据保存到Stock项目下，保留源文件路径、内容哈希、原始time、转换规则版本、单位、复权状态和质量标记。

1. 查找该批导出的原始脚本/快照，对照已知日期样本确认日线时间编码和时区。仅对已确认来源采用转换规则。
2. 明确日线与分钟线价格复权属性、成交量单位；补公司行动与正确的收益序列。
3. 对指数与精度损失的分钟线重新获取原始数据，重新导出；隔离流程不能覆盖源文件。
4. 补ETF数据、财务公告时点、历史证券状态、历史行业、成交额和交易规则。
5. 校验交易日历、各证券的历史可用区间、真实停牌情况和缺失原因后，再建立回测输入快照。
