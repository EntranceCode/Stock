# A股与场内ETF混合策略系统 实施设计 v1.0

本文档是从零到"能运行并验证策略"的完整实施设计。它替代此前按数据集罗列的补丁式记录，
并按依赖顺序重排：**字段供给 → 数据契约 → 采集归档 → 数据集判据 → 引擎 → 验收 → 运维**。

策略规则本身不在本文重写，见 [混合策略系统设计](hybrid-system-design.md)；本文把它当作已确定的输入。

## 0. 三条不可协商的原则

1. **先确认供给，再定契约。** 此前的错误顺序是先写死必填字段，再发现无人能提供。
2. **判据优先于清单。** 每一条"未完成"都必须能写成可执行的判定；写不出判定的条目不得进入清单。
3. **降级必须显式。** 任何字段、证券或模块若因证据不足而不用，必须留下记录并进入结论限定，
   不得用零值、近似值或单一默认桶掩盖。

## 1. 终态与"完成"的定义

### 1.1 终态

一个能对三个策略模块及其组合给出**可采信、可重复、可追溯**回测结论的系统。

### 1.2 "能验证策略"的可操作定义

同时满足以下六条，才算能够验证策略。任何一条不满足，输出只能称为机制演示。

| # | 条件 | 判定方式 |
|---|---|---|
| C1 | 无存活偏差 | universe 由当时可得信息重建，退市证券在其存续期内可被选中 |
| C2 | 无未来信息 | 属性测试证明任何决策时刻都读不到该时刻之后的信息 |
| C3 | 可成交性成立 | 每笔成交都在当时可交易、未涨跌停锁定、未超成交额容量 |
| C4 | 账务可对账 | 独立重建现金流与持仓，与引擎输出分毫不差 |
| C5 | 样本外封存 | 最后 20% 只在最终评估时读取一次，读取即记录 |
| C6 | 结论有限定 | 每条降级（字段、行业、成分、版本）都写进结论的适用条件 |

### 1.3 范围红线（明确不做）

不做盘中与分钟级、不做空与融资、不做北交所（首版）、不做跨境 ETF（交易日历与溢价数据未备）、
不做实盘与券商接口、不做机器学习因子。

## 2. 阶段 0：字段供给调研（**不写代码**）

本阶段唯一交付物是 2.1 与 2.2。阶段退出条件：每个必填字段都落入三种供给状态之一，
且每个"需约定"字段都有已记录的决策编号。

### 2.2 六项决策（需项目所有者确认）

每一项都必须显式记录选择与理由，**不得由实现者默认**。

**D1 — bar 的 available_at 口径**

| 选项 | 含义 | 代价 | 影响 |
|---|---|---|---|
| D1-a | 交易日收市后固定延迟（如 18:00） | 无 | 覆盖率 100%，结论含"假设收市后可得" |
| D1-b | 次一交易日 00:00 | 无 | 更保守，日频策略通常等价 |
| D1-c | 来源时间戳 | 需每源提供 | 现实上多数源不提供 |

**建议 D1-b**：与财务层已采用的"公告日 + 1 天"一致，保守且不引入新的假设种类。

**D2 — 财务版本口径**（决定股票能否进入选股）

| 选项 | 含义 | 代价 | 结论强度 |
|---|---|---|---|
| D2-a | 必须核验首次披露版本 | 约 17 万份公告，且仍可能无法对齐 | 最大 | 最强 |
| D2-b | 接受供应商最新版，仅当"未发现重述证据"时可用 | 低（已有分类：79.5% 可由跨年对比解释、14.6% 未修订） | 弱：结论限定于"未发生重述" |
| D2-c | 只在已核验的少数证券上做因子研究 | 中 | 中：样本受限 |

**已决定：D2-b（2026-10-26）**。理由是 D2-a 的代价与不确定性都极高，而 D2-b 至少能给出一个诚实且带限定的结论；"当作已核验"在任何方案里都不可选。

实现方式为**逐行判定**而不是整库一刀切：`financial_availability` 已把 137,714 行分类，其中 `unrevised`（14.6%）与 `next_year_comparable`（79.5%）合计 94.1% 可置为已核验，`unexplained`（5.9%）保持未核验并继续被引擎排除。因子层据此逐条写入 `original_version_verified`，未核验的观测追加 `first_disclosure_unverified:<分类>` 原因。

**结论的强制限定**：凡使用本版本的因子，回测结论必须写明"在未发现重述证据的条件下"，并说明 5.9% 的观测因修订证据无法解释而未参与选股。

已知缺口：用于发现"数据集就绪但引擎全部拒绝"这一矛盾的判据（`engine_usable_share`）已实现但**尚未注册**——就绪夹具的可用时间层没有文件清单，无法在不伪造行的情况下评估。注册前该矛盾只能靠因子层的逐条排除暴露。

**D3 — 成交量口径**：股数还是手？需抽样比对成交额/均价反推，记录不一致率。

**D4 — tradable/buyable/sellable 推导规则**：由停牌状态、涨跌停是否触板、上市首日/复牌首日、
卖出锁定期（T+1）共同决定。必须写成可测试的判定函数。

**D5 — 历史行业分类缺失的处理**：显式关闭行业上限约束，并在结论中写明"未做行业中性化"。

**D6 — 公司行动到账日**：以除权日为基准加固定交易日数，或以公告披露的到账日（部分有）。

## 3. 阶段 1：数据契约（由供给矩阵反推）

### 3.1 契约原则

1. **可构造性优先**：无法由已确认供给填充的字段，不得设为必填。
2. **必填字段必须能被拒绝**：构造即校验，缺失即抛错，不得有空值兜底。
3. **未知与零可区分**：缺失用 None，不得用 0；0 是合法观测值。
4. **快照不可变**：构造时复制，调用方不得改变已构造快照的观测内容。

### 3.2 核心对象

| 对象 | 必填字段 | 可选/降级字段 |
|---|---|---|
| SecurityMaster | symbol, exchange, asset_type, list_date, delist_date | 行业分类（D5 降级）、交易权限、规则生效区间 |
| DailyBar | trade_date, OHLC, volume, **turnover**, **available_at**, adjusted_close | 停牌标记、涨跌停价格、tradable/buyable/sellable（D4 后转必填） |
| Fundamental | symbol, 报告期, announced_at, available_at, value, 口径版本（D2） | 首次披露标记 |
| CorporateAction | symbol, 类型, ex_date, 份额变化, 现金流（分口径） | 到账日（D6）、税务 |
| Constituent | ETF, 标的指数, effective_at, available_at | 权重（C 状态，降级） |

### 3.3 契约的验收测试

- 构造任意字段缺失的对象必须抛错（逐字段）。
- 相同输入构造出的快照必须相等且不可被外部改写。
- 决策时刻之后的任何 bar 不得出现在可观测历史中（属性测试）。

## 4. 阶段 2：采集与归档

### 4.1 来源分层

| 层 | 含义 | 例 |
|---|---|---|
| ① 原始出处 | 真正产出数据的主体 | 交易所行情、发行人公告、休市通知 |
| ② 官方渠道 | 出处自己发布 | 上交所/深交所网站、巨潮 |
| ③ 商业再分发 | 转售上游 | BaoStock、通达信、eastmoney |
| ④ 本项目加工 | 自己计算 | 复权、可用时间、涨跌停推导 |

**判定同源**：上游是否同一份原始发布；加工链路是否独立；失败模式是否相关。
互为回退只在上游或失败模式不同时成立。

### 4.2 冲突处理（五类，不得用一条规则覆盖）

| 类型 | 处理 | 记录 |
|---|---|---|
| 数值冲突 | 该字段置空，不得置零 | field_conflict |
| 覆盖冲突 | 有值者可用，但不得据此认定可交易 | coverage_disagreement |
| 时点冲突 | 取较晚可得时间 | available_at_conservative |
| 口径冲突 | 不算冲突；适配器必须显式声明映射，未声明即报错 | 适配器映射表 |
| 完整性冲突 | 以已核验日历为准，不得填充缺失日 | session_gap |

**禁止**：优先级仲裁（落选值退出证据体系）、行级合并（合并行不对应任何原始响应，哈希链断裂）。

### 4.3 归档规范

- 每次采集一个带时间戳的运行目录；文件只写一次；清单记录每份文件的 SHA-256。
- 清单**每完成一个请求就原子重写**，使中断批次仍有完整归属。
- 原始响应与解析结果分开保存。
- 采集器必须有回执校验：回复必须与请求的参数尾部一致，否则记为失序而非成功。

### 4.4 采集器验收

用真实抓包回放验证：被接受的条数应等于成功条数，被拒条数应等于真实失败条数，**不得有误判**。

## 5. 阶段 3：数据集与闸门

### 5.1 每个数据集的验收判据（可判定）

判据必须能用一条查询回答通过与否。

| 数据集 | 判据 | 当前状态 |
|---|---|---|
| calendar | 与个股/ETF 实际 bar 反验冲突数为 0；两个交易所各自的年度公告齐备 | 满足 |
| stock_daily | 每证券 bar 缺日要么为 0 要么有 session_gap 记录；**turnover 覆盖目标 universe 的比例 ≥ 策略阈值且覆盖只数 ≥ 绝对下限**；涨跌停复验突破数 0；复权残留跳变逐条登记 | 成交额已满足（1,218/4,272 = 28.51%、0 空值）；缺日与涨跌停覆盖面未满足 |
| etf_daily | 同 stock_daily，且 universe 由当时上市信息重建 | 未满足（注册仅 6 只） |
| financials | announced_at 抽样核验通过率 ≥ 99%（记录样本与口径 D2） | 未满足（版本口径待 D2） |
| action_samples | 隔离条数 ≤ 全局 0.1% 且逐条有原因与原始证据 | 未满足（5/26621，需逐条归档） |
| security_metadata | 挂牌与终止上市名单覆盖目标板块；退市边界可判定 | 未满足 |

### 5.2 readiness 是计算结果，不是声明

`readiness = 全部判据的合取`，每次评估把每条判据的结果与证据路径写入清单。
**不得**用手写的 backtest_ready 字段作为唯一来源——手写字段会漂移，已经漂移过。

**阈值写在配置里，不写在代码里。** `config/readiness-policy.json` 保存 `stock_turnover` 的 `coverage_threshold` 与 `minimum_covered`，并附 rationale 与 remainder_rule。这样评审者可以质疑阈值本身，而不只是质疑阈值的实现；缺策略文件时判据失败关闭，不取默认值。

**绝对下限不可省。** 只按比例判定是可被规避的——把 universe 声明得足够小，覆盖率自然趋近 100%。因此覆盖比例与覆盖只数必须同时满足。

**未覆盖部分必须进入结论。** 判据在 detail 中报出被排除的只数；被排除的证券不得进入选股，且必须作为范围限定写入回测结论（remainder_rule）。

### 5.3 闸门行为

准入关闭时 `check-data` 返回非零；**不提供强制跳过开关**；机制验证须显式传参，并逐行记录。

## 6. 阶段 4：引擎

### 6.1 模块职责

| 模块 | 职责 | 不变量 |
|---|---|---|
| strategies | 三模块目标权重 | 只做多；无有效因子不排名；无合格标的不满仓 |
| portfolio | 合并预算、风控 | 风控只减不增；权重和 ≤ 预算；缺预算留现金 |
| accounting | 订单、成交、持仓、现金 | 现金不为负；未解锁不得卖出；账务可独立重建 |
| backtest | 逐时点推进 | 决策只用当时可得信息 |
| snapshot_series | 逐时点快照构建 | 契约字段缺一即排除并记因 |
| factors | 时点质量/价值 | 缺失不填零；负利润不给 value；版本未核验恒为 False |

### 6.2 保留与重建边界

现有引擎约 3,475 行、220 项检查（含未来函数属性测试），**其核心逻辑经实现与设计逐条核对一致**，
建议整体保留，仅按第 3 节修订契约字段。重建引擎不会解决本文指出的任何问题，
而会重新引入未来函数风险。

### 6.3 接口

引擎只消费快照，不感知数据来源；来源差异必须在构建快照前降级为字段缺失。

## 7. 阶段 5：验收与首次回测

### 7.1 四类比较（缺一不可）

1. 可投资宽基 ETF 买入持有基准
2. 三个模块各自单独运行
3. 固定 40/35/25 组合、统一风控组合、逐一去掉模块的消融
4. 风险匹配的静态组合（排除"只是少持权益"的表面改进）

### 7.2 时间切分

60% 开发 / 20% 方案选择 / 20% 封存；滚动 36 个月 + 12 个月。
封存段只读一次，读取行为本身入库。

### 7.3 输出与红线

扣费年化、最大回撤、年化波动、夏普、卡玛、换手、费用占比、回撤恢复时间、持仓集中度、无法成交比例；
佣金敏感性与 5/10/20 基点滑点、额外延迟一天、参数邻域、不同市场阶段。

红线（任一失败即整次无效）：负现金、未解锁卖出、超量卖出、账务重建不一致、实际持仓超限无处置记录。

## 8. 阶段 6：运行与运维

1. **每日增量**：只取最后一根 bar 之后的区间追加。
2. **修订检测**：来源若给出修订标记或更新日期变化，**重取该区间**，不得盲信追加。
   金融历史数据不是只增不减的时序流，这是与常见行情缓存方案的关键差异。
3. **失败恢复**：清单可续跑；连续失败达阈值即停并报警，不得静默跳过。

## 9. 三条终止线

设计必须包含何时停止，否则会无限修补。

| 终止线 | 触发条件 | 处置 |
|---|---|---|
| T1 口径不可用 | D2 选 D2-a 且公告获取成本超预算、或对齐失败率过高 | 改用 D2-b，并把结论限定为"未发生重述条件下" |
| T2 可交易性不可判定 | D4 无法给出可测试的判定 | 缩小结论范围至"可交易标记明确的证券"，并在结论写明 |
| T3 数据不足 | 补充后仍有 ≥30% 证券无法满足 C1–C3 | **明确结论：用可获取的数据无法验证该策略假设**，停止投入 |

T3 是一个合法且有价值的结论，必须在设计阶段就被允许。
